# Lab2 实验报告：地址空间与内存管理

## 一、实验目标

理解 RISC-V SV39 页表和地址空间隔离，完成第四章中依赖虚拟地址翻译的系统调用，包括时间查询、内存读写跟踪、匿名内存映射与解除映射。

## 二、主要实现

### 1. 支持虚拟地址的 sys_get_time

第四章中，用户程序和内核使用不同的地址空间，因此不能直接把用户传入的虚拟地址当成内核指针写入。

实现时先调用 get_time_us 获取时间，构造包含秒和微秒的 TimeVal，再通过 translated_byte_buffer 将用户缓冲区转换为对应的物理内存切片，逐段复制时间数据。

这种方式也能处理 TimeVal 跨越两个页面的情况。

### 2. 实现 sys_trace

根据 trace_request 区分三种操作：

- 0：读取用户指定地址的一个字节。
- 1：向用户指定地址写入一个字节。
- 2：查询当前任务调用指定系统调用的次数。

读写内存时，使用当前任务的页表进行地址翻译，检查页表项有效位、用户访问权限以及读写权限。不满足要求时返回 -1。

查询系统调用次数时，id 表示系统调用编号，因此必须先处理该请求，再进入内存地址翻译逻辑。

### 3. 按任务统计系统调用次数

在 TaskManagerInner 中使用 Vec<[usize; 512]> 保存计数，每个任务拥有独立的计数数组。

在 syscall 分发入口记录调用次数，再执行具体系统调用。这样查询 SYSCALL_TRACE 次数时，本次查询本身也会被计入。

访问计数表时通过 UPSafeCell 获取内部数据，操作完成后释放借用，不将借用保留到任务切换期间。

### 4. 实现 sys_mmap

检查起始地址是否按页对齐、长度是否为零、地址加法是否溢出，以及权限参数是否合法。

权限仅允许读、写、执行三个标志，并拒绝权限全部为零的请求。

检查目标范围内是否存在有效映射，确认没有冲突后，通过 insert_framed_area 分配物理页并建立用户映射。非整页长度按页向上取整。

### 5. 实现 sys_munmap

根据起始地址和向上取整后的结束地址，在 MemorySet 中寻找匹配的用户 Framed 区域。

找到后移除该区域，调用 MapArea::unmap 清除页表映射，并通过 FrameTracker 的释放回收数据页。

当前实现按完整 MapArea 解除映射，尚未实现任意子区间的区域拆分。

## 三、遇到的问题与解决方法

### 1. 添加计数后出现编译错误

最初将 syscall_times 声明在循环内部，导致初始化 TaskManagerInner 时找不到该变量。

调整大括号位置，将声明移到循环外部，使计数表和任务列表处于同一作用域。

新增的公开函数还触发了 missing_docs 检查，通过补充文档注释解决。

### 2. PAGE_SIZE 导入失败

最初从 mm 模块导入 PAGE_SIZE，但该常量定义在 config 模块。

将导入路径改为 crate::config::PAGE_SIZE 后解决。

### 3. 相邻页面无法继续映射

最初使用 translate(vpn).is_some() 判断页面是否已被占用，导致 ch4_unmap 中第二次 mmap 失败。

原因是返回 Some 只表示找到了页表项，其有效位仍可能为零。

修改为进一步检查 pte.is_valid()，才正确区分已映射页面和空闲页面。

### 4. 非法权限被错误接受

修正页表项检查后，发现权限为零的 mmap 请求返回了成功。

补充 port == 0 检查后，该测试通过。

### 5. 如何理解检查器的 4/16

发生编译错误时，检查器没有获得用户程序的正常输出，但四项“禁止出现的错误字符串”检查仍可能通过，因此显示 4/16。

这不代表内核实际运行了测试。排查时应先确认编译成功，再查看具体断言和最终统计。

## 五、实验总结

本次实验让我理解了用户虚拟地址不能由内核直接解引用，必须通过当前任务的页表转换后访问。

同时，我认识到“存在页表项”和“存在有效映射”是不同的概念。实现内存管理时，需要同时考虑地址范围、页面对齐、权限、映射冲突和物理页的生命周期。

后续可以继续完善部分解除映射、非法用户指针检查以及内存分配失败时的错误处理。
